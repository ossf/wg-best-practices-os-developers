# PySCG 1.0.0

Released: 2026-04-24
Targets: CPython >= 3.9

Initial published release with 48 `pyscg-XXXX` rule's across the nine matching content scope of secure coding guides for other languages such as Java or Perl.

## Background

This guide when through several transitions originating on a non git based company internal page, into markdown in
As of 2026 we moved the content from a subfolder in `ossf/wg-best-practices-os-developers` to `ossf/python-secure-coding-guide`.
First major release was in March 2026 as per [Secure Coding Guide for Python (pyscg) First Release](https://openssf.org/blog/2026/05/12/secure-coding-guide-for-python-pyscg-first-release/)

Major efforts shaped the content that became 1.0.0:

* __Content import__ — the guide's material was moved from an internal resource
  onto GitHub, initially listing the rules under their original naming
  ([#531](https://github.com/ossf/wg-best-practices-os-developers/issues/531)).
* __MITRE CWE de-confliction__ — to avoid confusing the guide's rules with MITRE
  CWE numbers and titles, rules were given their own `pyscg-XXXX` IDs and the
  content was reorganized into chapters/sections with revised titles
  ([#894](https://github.com/ossf/wg-best-practices-os-developers/issues/894),
* Organized into book sections via [#849](https://github.com/ossf/wg-best-practices-os-developers/issues/849),
* Titles normalized via [#1017](https://github.com/ossf/wg-best-practices-os-developers/issues/1017)).

## Release run (what led to 1.0.0)

* Guide-wide rule title normalization across all sections — Title Case,
  action-oriented, consistent naming ([#1017](https://github.com/ossf/wg-best-practices-os-developers/issues/1017)).
* Section 04 (neutralization) reorganized and titles grouped.
* Draft status removed from `readme.md`; version scheme added to the contributing
  guide ("first release" preparation).
* Final polish: updated Python and OWASP version references, bibliography header
  fixes, and web-version fix ([#1092](https://github.com/ossf/wg-best-practices-os-developers/pull/1092)).
